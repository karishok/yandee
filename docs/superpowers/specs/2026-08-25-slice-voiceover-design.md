# slice_voiceover — нарезка озвучки из Logic на wav по словам (дизайн)

Дата: 2026-08-25
Статус: утверждено пользователем, готово к планированию реализации

## 1. Обзор и границы

`record_voiceover.dart` записывает по одному слову через `ffmpeg
-f avfoundation` (микрофон Mac), и это упирается в известный дефект
захвата на этом пути (щелчки, см.
`2026-08-22-click-artifact-warning-design.md`) — даже с починкой
(`repairClickArtifact`) и предупреждением, часть дублей всё равно
звучит с артефактом. Пользователь хочет наговорить слова в Logic Pro
(чистый профессиональный тракт, без avfoundation) и получить готовые
`assets/*.wav` из экспортированного дубля.

Запись ведётся **по сценам**, а не всем списком сразу: 6 отдельных
Logic-сессий/bounce-файлов — `system` (4 фразы) и по одной на каждую из
5 сцен (`home`, `kitchen`, `farm`, `street`, `bathroom`). В каждой
сессии слова наговариваются **по порядку** объявления в
`scene_vocabulary.dart`/`voiceover_tasks.dart`, одним дублем, с паузой
между словами (ориентир — пауза ≥1с). Bounce из Logic — 16-bit PCM WAV
(тот же формат, что уже использует весь проект), только sample
rate/число каналов могут отличаться от `44100/mono`.

Все ассеты для этой сцены перезаписываются целиком — без сверки с тем,
что уже записано (`isUnrecorded`/`buildRecordingQueue` тут не
участвуют), потому что позиционное сопоставление «i-й найденный кусок
тишины → i-я задача» требует полного, фиксированного списка на вход.

### Что входит в этот дизайн

- Новый CLI-инструмент `tool/slice_voiceover.dart`: на входе — id сцены
  (или `system`) и путь к bounce-файлу, на выходе — записанные
  `assets/*.wav` для всех слов этой сцены.
- Новый чистый модуль `tool/src/silence_split.dart` — детекция границ
  слов по тишине в `Float64List` сэмплов.
- Проверка количества найденных кусков против ожидаемого числа слов
  сцены, с диагностикой при несовпадении.

### Осознанно вне рамок

- Изменения в `record_voiceover.dart` (mic-путь остаётся как есть, на
  случай если он ещё понадобится) и в `wav_io.dart`/`denoise_audio.dart`.
- Поддержка входных bounce-файлов не в 16-bit PCM — пользователь
  подтвердил, что будет присылать 16-bit, конвертация битности не
  нужна.
- Интерактивное прослушивание/подтверждение каждого куска в терминале —
  пользователь уже слышал все слова при записи в Logic; при
  несовпадении количества инструмент просто останавливается с
  таймкодами (см. §4), без review-режима.
- Автоматическая проверка совместимости плеера (`audioplayers`) с
  форматом файла — не нужна: итоговый формат 16-bit/44.1kHz/mono,
  идентичен уже проигрываемым в приложении файлам.

## 2. CLI и нормализация входа

```
dart run tool/slice_voiceover.dart <scene-id|system> <path/to/bounce.wav>
```

- `<scene-id|system>` — обязательный позиционный аргумент, те же
  значения, что уже принимает `isValidSceneFilter`/`taskMatchesFilter`
  из `voiceover_queue.dart`.
- `<path/to/bounce.wav>` — экспортированный из Logic дубль для этой
  сцены.
- Задачи: `buildVoiceoverTasks().where((t) => taskMatchesFilter(t,
  sceneFilter))`, в порядке объявления — без фильтрации по
  `isUnrecorded`.

Перед нарезкой bounce нормализуется через уже используемый в проекте
`ffmpeg` (та же зависимость, что и в `record_voiceover.dart`) —
приводится к моно/44.1kHz, битность не трогается (вход уже 16-bit):

```
ffmpeg -i bounce.wav -ar 44100 -ac 1 -y <tmp>.wav
```

Результат читается существующей `readMonoWav16` из `wav_io.dart` —
дальше всё работает в чистом Dart на `Float64List` сэмплов, без
дальнейших вызовов внешних процессов.

## 3. Нарезка по тишине (`tool/src/silence_split.dart`)

Новая чистая функция, в том же стиле, что `click_detector.dart`/
`denoise.dart` — принимает сэмплы и sample rate, не знает про файлы:

```dart
class WordSegment {
  const WordSegment({required this.startSample, required this.endSample});
  final int startSample;
  final int endSample;
}

List<WordSegment> splitOnSilence(
  Float64List samples,
  int sampleRate, {
  double windowMs = 20,
  double silencePercentile = 0.2,
  double thresholdMultiplier = 4,
  double minWordMs = 150,
  double minSilenceMs = 500,
  double padMs = 50,
});
```

**Алгоритм:**

1. RMS-огибающая по неперекрывающимся окнам `windowMs` (~20мс) —
   `envelope[i] = rms(samples[i*win .. (i+1)*win])`.
2. Адаптивный порог тишины: `noiseFloor` = `silencePercentile`-й
   процентиль значений огибающей по всему клипу (тот же приём, что
   `reduceNoise` использует для оценки шумового пола по спектру — здесь
   то же самое, но по амплитудной огибающей). Порог = `noiseFloor *
   thresholdMultiplier`. Это подстраивается под шумность конкретного
   дубля вместо фиксированного dB-значения.
3. Окна выше порога группируются в непрерывные пробеги; пробег короче
   `minWordMs` отбрасывается как случайный всплеск (дыхание, шорох).
4. Пробег тишины между двумя словами короче `minSilenceMs` не считается
   разделителем — слова, между которыми не выдержана пауза, склеятся в
   один кусок (что и даст несовпадение количества, см. §4, а не тихую
   порчу данных).
5. Каждый оставшийся пробег расширяется на `padMs` в обе стороны
   (clamped к границам клипа) — чтобы не обрезать тихие
   начало/окончание слова (мягкие согласные, затухание).

Результат — список сегментов в порядке появления в файле.

## 4. Сверка количества и диагностика

`slice_voiceover.dart` сравнивает `segments.length` с
`tasks.length` для выбранной сцены.

- **Совпадает** → переход к §5.
- **Не совпадает** → ничего не записывается (all-or-nothing), в stderr
  печатается таблица всех найденных сегментов — индекс, начало/конец/
  длительность в секундах — и ожидаемое число слов, например:

  ```
  Ожидалось 12 слов (home), найдено 11 кусков:
    0: 0.42–0.91с (0.49с)
    1: 1.60–2.15с (0.55с)
    ...
  Проверь дубль в Logic на волну — где-то не хватает паузы (слова
  склеились) или пауза внутри слова (слово разрезано).
  ```

  Процесс завершается с ненулевым кодом выхода.

## 5. Очистка и запись

Для каждой пары `(segments[i], tasks[i])` по порядку:

1. Вырезать `samples[segment.startSample .. segment.endSample]`.
2. Прогнать через уже существующий `cleanRecording()` из
   `denoise.dart` (`highPass` → `reduceNoise` → `fadeEdges`) — тот же
   пайплайн очистки, что применяется к mic-записям, для единообразия
   громкости/шумового пола со старыми словами и чтобы паддинг по
   тишине не оставил щелчок на границе.
3. `writeMonoWav16` в `task.outputPath` (создать директории при
   необходимости).

По завершении — сводка в stdout: сколько слов записано и куда (по
аналогии с финальным `Готово!` в `record_voiceover.dart`).

## 6. Тестирование

`splitOnSilence` — чистая функция, тестируется синтетическими
сигналами без реального Logic/ffmpeg (как `click_detector_test.dart`):

- Тишина → пустой результат.
- N синтетических тонов, разделённых тишиной длиннее `minSilenceMs` →
  находит ровно N сегментов на ожидаемых границах.
- Два тона, разделённые слишком короткой тишиной (< `minSilenceMs`) →
  схлопываются в один сегмент (проверяет разделение при несовпадении
  количества, не тихую поломку).
- Короткий всплеск (< `minWordMs`) окружённый тишиной → не считается
  словом.
- Паддинг: сегмент включает `padMs` по обе стороны от фактических
  границ громкого участка, не вылезая за пределы клипа на первом/
  последнем слове.

Интеграционная часть (`slice_voiceover.dart` целиком — ffmpeg,
файловый ввод-вывод) тестируется вручную, как и `record_voiceover.dart`
— требует реального bounce-файла из Logic.
