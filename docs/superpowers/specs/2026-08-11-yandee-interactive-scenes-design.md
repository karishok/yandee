# Yandee — интерактивные обучающие сцены (дизайн)

Дата: 2026-08-11
Статус: утверждено пользователем, готово к планированию реализации

## 1. Обзор и границы

**Продукт:** Yandee — набор интерактивных обучающих сцен для детей 1–3 лет.
Ребёнок открывает сцену (например, «Город»), видит статичную иллюстрацию
примерно с 10 объектами и может:

- **Режим «Исследовать»** — тапнуть по любому объекту → услышать его
  название (заранее записанное аудио).
- **Режим «Найди»** — приложение просит найти конкретный объект;
  неверный тап даёт мягкую подсказку и не сбрасывает прогресс, верный —
  переходит к следующему ненайденному объекту, пока не найдены все.

Родитель физически рядом, но не обязан выполнять действия вместе с
ребёнком на каждом шаге (в отличие от прежней концепции с видео и
обязательными паузами). Родитель вручную выбирает режим переключателем
на экране сцены.

Приложение — продукт для публикации в App Store и Google Play
одновременно (Flutter, кросс-платформенно из одной базы кода).
Контент — собственного производства (не лицензированный и не
пользовательский).

### Что входит в этот дизайн

- Экран списка сцен и экран сцены (оба режима)
- Контроллер игровой логики с расширяемой моделью режимов
- Формат контента сцены (JSON-схема) и контракт с хостингом контента
- Стратегия загрузки, кэширования и офлайн-работы
- Обработка ошибок сети/воспроизведения
- Стратегия тестирования

### Осознанно вне рамок MVP (зафиксировано как решение)

- Аккаунты и вход — их не будет; профиль ребёнка не хранится
- Детские профили и возрастная фильтрация — вся библиотека рассчитана
  на единый диапазон 1–3 года
- Трекинг прогресса/статистики просмотров
- Монетизация/подписка — планируется позже; архитектура не должна
  мешать добавить paywall, но сам paywall не проектируется сейчас
- Инструментарий контент-команды для заливки файлов на хостинг —
  фиксируется только формат контента и протокол, которым пользуется
  приложение
- Старый видеоплеер-скелет (`video_content.dart`,
  `video_player_screen.dart`, `interaction_service.dart`,
  `parent_prompt_overlay.dart`, зависимость `video_player`) — удаляется
  полностью, механика с ним не связана

### Точка расширения: дополнительные режимы в будущем

Помимо «Исследовать» и «Найди», в будущем планируются другие режимы
поверх той же сцены и тех же объектов — например «Факт о предмете»
(развёрнутый рассказ об объекте) или «Последовательность предметов»
(найти объекты в заданном порядке). Архитектура (раздел 3) закладывает
это через абстракцию режима с самого начала, не требуя переделки при
добавлении новых.

## 2. Модель данных и контент-контракт

Контент (JSON-манифест сцены + картинка + аудиофайлы объектов)
раздаётся со статического хостинга (объектное хранилище + CDN,
без выделенного бэкенд-сервиса — персонализации и аккаунтов нет).

### `scene.json`

```json
{
  "id": "city",
  "version": 3,
  "title": "Город",
  "minAgeMonths": 12,
  "background": "background.png",
  "objects": [
    {
      "id": "tree_1",
      "label": "Дерево",
      "audio": "tree_1.mp3",
      "rect": { "x": 0.12, "y": 0.45, "width": 0.10, "height": 0.20 }
    }
  ]
}
```

- `rect` задаётся в нормализованных координатах (0..1 от размеров
  картинки), не в пикселях — не зависит от разрешения экрана
  устройства. Зоны тапа — прямоугольники (не полигоны): проще в
  производстве контента и в hit-testing, для объектов размером
  с палец ребёнка 1–3 лет точности достаточно.
- `version` — целое число, растёт при любом изменении контента сцены;
  используется для кэш-инвалидации на клиенте.
- Поля объекта уже покрывают оба текущих режима. Будущие режимы
  добавляют свои поля как необязательные (например `funFactAudio`,
  `sequenceOrder`), не ломая уже выпущенные сцены и старые версии
  приложения, которые их не читают.

### Индекс-манифест

Единая точка входа, отдаётся с хостинга по фиксированному URL:

```json
{
  "scenesVersion": 7,
  "scenes": [
    { "id": "city", "version": 3, "title": "Город", "thumbnail": "city/thumb.png" },
    { "id": "farm", "version": 1, "title": "Ферма", "thumbnail": "farm/thumb.png" }
  ]
}
```

Приложение сравнивает `scenesVersion` и версии отдельных сцен со своим
локальным кэшем, чтобы определить, что нужно скачать или обновить.

### Dart-модели

Зеркалят JSON-схему: `SceneManifestEntry`, `Scene`, `SceneObject`,
`ObjectRect`. Поля под будущие режимы, которых код пока не использует,
допускаются как необязательные и просто игнорируются текущей версией
приложения.

## 3. Архитектура приложения

### Слои

- **Data** — `ContentRepository`: скачивает манифест/сцены с хостинга,
  кэширует в локальной файловой системе (`path_provider`), сравнивает
  версии, отдаёт наверх уже готовые модели домена.
- **Domain** — модели из раздела 2 плюс абстракция режима:
  интерфейс `SceneMode` (методы вроде `activate()`,
  `onObjectTapped(object)`) с реализациями `ExploreMode` и `FindMode`.
  Это и есть точка расширения под будущие режимы — новый режим
  добавляется как новый класс, реализующий `SceneMode`, без изменений
  в контроллере или экране.
- **Presentation** — экраны и `SceneController` (`ChangeNotifier`,
  в духе нынешнего `InteractionService`), который держит текущую
  сцену, активный `SceneMode` и делегирует ему обработку тапов.
  Управление состоянием — через уже используемый в проекте пакет
  `provider`.

### Экраны

1. **`SceneListScreen`** (главный экран) — сетка карточек сцен из
   локального кэша; в фоне обновляет манифест и докачивает
   новые/обновлённые сцены. Если кэш пуст и сети нет — экран
   с сообщением и кнопкой повтора.
2. **`SceneScreen`** — иллюстрация на весь экран (`LayoutBuilder`
   считает размеры контейнера) со `Stack` невидимых
   `GestureDetector`-зон, спозиционированных по `rect` из JSON
   (перевод нормализованных 0..1 координат в пиксели контейнера).
   Открывается по умолчанию в режиме «Исследовать»; в углу экрана —
   переключатель режима для родителя.

   В режиме «Найди» `FindMode` перебирает объекты сцены по кругу,
   пока не найдены все. После того как найден последний — играет
   туш, поверх сцены на пару секунд показывается лёгкая анимация
   поздравления, затем режим автоматически возвращается к
   «Исследовать» (родитель в любой момент может переключить снова).
   Экран сцены не закрывается сам — выход к `SceneListScreen` только
   по явному действию (кнопка назад).

### Аудио

Единый `AudioPlayerService` (обёртка над пакетом `audioplayers`)
поверх двух источников звука:

- **аудио объектов** — из контента сцены (поле `audio` в схеме);
- **системные фразы** — не зависят от сцены, лежат в ассетах
  приложения: интро «Найди:», мягкий сигнал при неверном тапе,
  весёлый — при верном, туш — по завершении режима «Найди». Режим
  «Найди» склеивает системную фразу-интро с уже существующим
  аудио-названием объекта — отдельный «промпт»-файл на каждый объект
  в каждой сцене не нужен.

## 4. Доставка контента, кэш и обработка ошибок

### Загрузка и кэш

- При каждом запуске приложения (если есть сеть) `ContentRepository`
  скачивает индекс-манифест и сравнивает `scenesVersion`/версии сцен
  с локально сохранёнными.
- Изменившиеся/новые сцены докачиваются в фоне (картинка, аудио,
  `scene.json`) в директорию приложения; уже играбельные сцены не
  блокируются на время докачки других.
- Экран сцен всегда рисуется по локальному кэшу — сеть используется
  только для проверки обновлений и докачки, не для показа контента
  напрямую. Это даёт полноценную офлайн-работу после первой загрузки
  (важно для использования в дороге).
- Частично скачанная сцена не подменяет предыдущую рабочую версию в
  кэше, пока не скачается полностью: сначала во временную папку,
  затем атомарное переключение.
- Публикация новой или обновлённой сцены контент-командой не требует
  релиза приложения в App Store/Google Play — только загрузку файлов
  на хостинг и обновление индекс-манифеста. Релиз в сторы нужен
  только при изменении кода самого приложения.

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет сети, кэш пуст (первый запуск) | Экран «Нет подключения» с кнопкой повтора |
| Нет сети, кэш не пуст | Работаем по кэшу молча, без баннеров — ребёнок не должен видеть технические сообщения |
| Манифест скачался, но какая-то сцена не докачалась | Сцена не появляется/не обновляется в списке, попытка повторится при следующей проверке |
| Ошибка воспроизведения аудио | Тихо логируется и пропускается — игра не блокируется из-за звука |
| Тап мимо всех зон объектов | Игнорируется, никакой реакции |

## 5. Тестирование

- **Unit-тесты** — `ExploreMode`/`FindMode`: обработка верного и
  неверного тапа, условие завершения раунда «Найди» (все объекты
  найдены). `ContentRepository`: сравнение версий, кэш-инвалидация,
  атомарность обновления — с моками сети и файловой системы.
- **Widget-тесты** — `SceneScreen`: зоны тапа рендерятся в правильных
  координатах при разных размерах экрана; тап по зоне вызывает
  ожидаемый метод контроллера.
- **Ручная проверка** — прогон на реальном устройстве/эмуляторе.

## Итог

Yandee — офлайн-дружелюбное приложение из статичных иллюстрированных
сцен с зонами тапа, где контент обновляется с простого статического
хостинга без релизов в сторы. Игровая логика построена вокруг
подключаемых режимов (`SceneMode`), так что «Исследовать» и «Найди» —
только первые два из потенциально многих. Аккаунты, профили, прогресс
и монетизация осознанно исключены из MVP, но модель данных и
архитектура не мешают добавить их позже.
