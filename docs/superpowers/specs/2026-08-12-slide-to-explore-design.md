# Yandee — скольжение пальцем по сцене (дизайн)

Дата: 2026-08-12
Статус: утверждено пользователем, готово к планированию реализации

## 1. Проблема

Целевой возраст приложения — 1–3 года (см.
`docs/superpowers/specs/2026-08-11-yandee-interactive-scenes-design.md`).
Ребёнок в этом возрасте обычно не делает чистый «тап» (палец коснулся
экрана и оторвался на том же месте) — он ведёт пальцем по картинке, не
отрывая его, ожидая, что каждый предмет, над которым проходит палец,
отреагирует.

Сейчас это не работает. `SceneIllustration` кладёт на каждый предмет
сцены отдельный `Positioned(GestureDetector(onTap: ...))`. Flutter
маршрутизирует `PointerMoveEvent`/`PointerUpEvent` только тем
обработчикам, что участвовали в hit-тесте в момент `PointerDownEvent`
— по ходу движения пальца hit-тест не переигрывается. Значит, если
палец опустился вне зоны предмета (или в зоне другого предмета) и
затем скользит поверх нужной зоны, она никогда не узнаёт об этом
касании. Единственный на 100% рабочий сценарий сейчас — точный тап
точно в границах одной зоны без движения, что для этого возраста
скорее исключение, чем правило.

## 2. Что входит / не входит

**Входит:** новая модель попадания по объектам сцены — как для тапа,
так и для скольжения, с поддержкой нескольких одновременных пальцев
независимо друг от друга (например, ребёнок держит телефон одной
рукой, а другой водит по экрану).

**Не входит:**
- Любые изменения в `SceneController`, `ExploreMode`, `FindMode`,
  аудио-слое — они уже корректно обрабатывают частые/повторные вызовы
  `onObjectTapped` (прерывание текущего звука новым, дебаунс повторной
  фразы «Молодец», интерраптящийся «Попробуй ещё раз» при серии
  промахов в режиме «Найди») и не предполагают, что вызовы приходят
  только от «чистых» тапов.
- Пересчёт/правка `rect` у объектов сцены — не связано с этой задачей.
- Жесты, не являющиеся простым однопальцевым/двупальцевым
  прикосновением-и-скольжением (пинч-зум, поворот и т.п.) — сцена не
  масштабируется и не вращается, эта работа их не касается.

## 3. Модель взаимодействия

Один палец на экране — это одна независимая «сессия слежения»,
идентифицируемая `pointer.id` из Flutter (у каждого одновременного
касания свой уникальный id, назначаемый системой). Для каждого id
хранится текущий предмет, над которым сейчас находится этот палец
(либо ничего, если палец над пустым местом).

Правила срабатывания звука предмета:

| Событие | Реакция |
|---|---|
| Палец коснулся зоны предмета (`PointerDownEvent`) | Звук играет сразу |
| Палец, не отрываясь, вошёл в зону **другого** предмета | Звук нового предмета играет сразу — правило то же самое, что для тапа |
| Палец остаётся над тем же предметом, не выходя из зоны | Звук не повторяется |
| Палец ушёл в пустое место (вне всех зон) | Никакого звука, состояние просто сбрасывается |
| Палец **вернулся** в зону того же предмета после ухода | Считается новым «входом» — звук играет снова |
| Палец поднялся (`PointerUpEvent`/`PointerCancelEvent`) | Запись по этому `pointer.id` удаляется — следующее касание в том же месте это новый вход |

Каждый `pointer.id` обрабатывается полностью независимо: два
одновременных пальца в разных зонах реагируют оба, каждый по своим
правилам выше, не влияя друг на друга.

Приоритет при наложении зон объектов остаётся таким же, каким он
сейчас достигается порядком отрисовки в `Stack` (объект, стоящий
позже в списке `scene.objects`, «выше» и выигрывает у более раннего
объекта на пересечении) — просто вместо порядка виджетов в дереве это
теперь порядок перебора списка при собственном hit-тесте.

## 4. Реализация

Меняется один файл — `lib/presentation/widgets/scene_illustration.dart`
(и его тест). Список отдельных `Positioned(GestureDetector)` на
каждый объект убирается. Вместо него — один `Listener`
(`HitTestBehavior.opaque`), растянутый на весь `Stack` картинки, с
обработчиками `onPointerDown`/`onPointerMove`/`onPointerUp`/
`onPointerCancel`.

Внутри виджета: `Map<int, String?> _activeObjectIdByPointer` —
`pointer.id` → id текущего предмета под этим пальцем (или `null`).
Общая функция `SceneObject? _objectAt(Offset localPosition, Size
size)` переводит локальную точку в те же нормализованные координаты,
что сейчас использует `Positioned` (`rect.x * width` и т. д.), и
перебирает `scene.objects` в обратном порядке, возвращая первый
объект, чей `rect` содержит точку (или `null`, если ни один не
подошёл).

На каждом `PointerDownEvent`/`PointerMoveEvent` вычисляется объект в
текущей точке; если он отличается от того, что уже записан для этого
`pointer.id` (включая переход из/в `null`), запись обновляется, и если
новое значение не `null` — вызывается `controller.onObjectTapped(...)`
ровно как сейчас. На `PointerUpEvent`/`PointerCancelEvent` запись по
этому `pointer.id` удаляется.

`GestureDetector.onPan*` для этого не подходит: его распознаватель
жеста сливает несколько одновременных пальцев в одно общее
перемещение, а не отслеживает их независимо — что ломает требование
«два пальца работают одновременно и раздельно». Поэтому нужен именно
низкоуровневый `Listener` с ручным хранением состояния по
`pointer.id`.

## 5. Тестирование

`test/presentation/widgets/scene_illustration_test.dart` и
`test/presentation/screens/scene_screen_test.dart` сейчас находят зоны
объектов по ключу `ValueKey('object_zone_<id>')` и тапают их через
`tester.tap(...)`. Эти ключи и виджеты пропадают вместе со старой
реализацией — оба теста переписываются на симуляцию жеста по
координатам: та же математика (`rect.x/y/width/height` × размер
картинки на экране), что тест уже использует сейчас для проверки
позиции зоны, только вместо `tester.tap(zoneFinder)` — `tester.tapAt(
Offset(...))` / жест через `tester.startGesture(...)` на вычисленных
координатах внутри `SceneIllustration`.

Новое поведение получает отдельные тесты:
- **Скольжение через несколько предметов** — один непрерывный жест
  (`down` → серия `moveTo` → `up`) проезжает через координаты
  нескольких объектов подряд без отрыва пальца; проверяется, что звуки
  проигрались в том же порядке, в каком палец проходил зоны, и что
  задержка внутри одной зоны не даёт повторного звука.
- **Два одновременных независимых касания** — два `TestGesture` (через
  `tester.createGesture()`) одновременно входят в разные зоны;
  проверяется, что оба звука проиграли, независимо друг от друга.
- **Повторный вход в тот же предмет после ухода** — палец заходит в
  зону, выходит в пустое место, возвращается — звук должен проиграть
  дважды.

## Итог

Модель попадания по объектам сцены переходит от «дискретный тап по
виджету» к «какой предмет сейчас под каждым активным пальцем» —
единый источник правды и для тапа, и для скольжения, с независимой
поддержкой нескольких одновременных касаний. Изменение локализовано
в `SceneIllustration`; вся логика режимов и аудио ниже по стеку не
меняется, так как она уже спроектирована терпимой к частым и
повторным вызовам `onObjectTapped`.
