# Yandee — временная озвучка сцен через TTS (дизайн)

Дата: 2026-08-11
Статус: утверждено пользователем, готово к планированию реализации

## 1. Обзор и границы

Сейчас все аудио-ассеты в приложении — 50 названий объектов (5 сцен ×
10 объектов) и 4 системные фразы (`find_intro`, `correct`, `wrong_hint`,
`round_complete`) — это полностью тихие WAV-плейсхолдеры, генерируемые
`tool/generate_placeholder_assets.dart`. Этот дизайн заменяет их
настоящей (пусть пока и синтезированной) речью, не трогая код
приложения и формат контента.

**Подход — гибрид:** сейчас озвучиваем всё через TTS (голос `Milena`,
`ru_RU`, встроенный в macOS `say`) — бесплатно, офлайн, без
регистрации в сторонних сервисах. Настоящая запись живым голосом
(или облачный TTS вроде ElevenLabs/Yandex SpeechKit) добавляется
позже, отдельным проходом — она просто перезапишет содержимое тех же
файлов, без изменений в `scene.json` или в коде.

### Что входит в этот дизайн

- Скрипт-генератор озвучки на базе macOS `say` + `afconvert`
- Текст 3 коротких системных фраз (`find_intro` уже определён в
  исходном дизайне сцен как «Найди:»)
- Параметры голоса (скорость)
- Процесс прогона и проверки

### Осознанно вне рамок

- Облачный TTS / живая запись — следующий проход поверх той же
  инфраструктуры, не часть этой работы
- Любые изменения `scene.json`, `AudioPlayerService` или другого кода
  приложения — не требуются, воспроизведение уже устроено так, что ему
  всё равно, тишина в WAV-файле или речь
- CI/автоматический запуск генератора — это ручной dev-инструмент,
  как и существующий `generate_placeholder_assets.dart`

## 2. Архитектура

Новый скрипт `tool/generate_voiceover.dart`, рядом с
`generate_placeholder_assets.dart` и переиспользующий его список
`_scenes` (id/label по каждому объекту), чтобы словарь не дублировался
в двух местах.

Для каждого слова-объекта:

1. `say -v Milena -r 150 -o tmp.aiff "<label>"`
2. `afconvert -f WAVE -d LEI16@22050 -c 1 tmp.aiff <путь к .wav>`
3. Временный `.aiff` удаляется

Файлы пишутся в те же пути, что и сейчас:
`assets/demo_content/<scene>/<object_id>.wav`,
`assets/audio/system/<phrase>.wav`. `scene.json` не меняется —
менять нечего, поле `audio` уже указывает на эти же имена файлов.

## 3. Голос и текст фраз

- Голос: `Milena` (`ru_RU`) — единственный русский голос, доступный
  через `say` на этой машине
- Скорость: `-r 150` (медленнее дефолтных ~175–200 слов/мин —
  разборчивее для аудитории 1–3 года)
- Слова объектов — без изменений, берутся из существующих `label` в
  `_scenes` (например «Тарелка», «Светофор», «Дорожный знак»)
- Системные фразы:
  - `find_intro` → «Найди:» (уже определено в исходном дизайне сцен;
    на воспроизведении склеивается с аудио-названием объекта)
  - `correct` → «Молодец!»
  - `wrong_hint` → «Попробуй ещё раз»
  - `round_complete` → «Ура, ты всё нашёл!»

## 4. Гибридный статус — заметка на будущее

Вся озвучка на момент этого дизайна — TTS-заглушка, не финальный
контент. Явного флага в `scene.json` или в коде для этого не заводим
(минимально необходимое решение) — достаточно этой заметки в спеке:
при появлении живой записи или облачного TTS следующий проход просто
перезаписывает те же файлы по тем же путям, ничего в приложении
менять не нужно.

## 5. Прогон и проверка

- Разработчик вручную запускает `dart run tool/generate_voiceover.dart`
  (как и `generate_placeholder_assets.dart` сейчас — не хук, не шаг CI)
- Скрипт перезаписывает все 54 WAV-файла речью вместо тишины
- Проверка: `flutter analyze` + `flutter test` (код приложения не
  меняется — ожидаем, что оба остаются зелёными без правок) плюс
  ручное прослушивание нескольких файлов для sanity-check
- Бинарные `.wav` коммитятся в репозиторий — так же, как остальные
  ассеты сцен сейчас
