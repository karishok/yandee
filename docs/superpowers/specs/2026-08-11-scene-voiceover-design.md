# Yandee — озвучка сцен живым голосом (дизайн)

Дата: 2026-08-11
Статус: утверждено пользователем (пересмотрено — TTS заменён на запись
живым голосом), готово к планированию реализации

## 1. Обзор и границы

Сейчас все аудио-ассеты в приложении — 50 названий объектов (5 сцен ×
10 объектов) и 4 системные фразы (`find_intro`, `correct`, `wrong_hint`,
`round_complete`) — это полностью тихие WAV-плейсхолдеры, генерируемые
`tool/generate_placeholder_assets.dart`. Этот дизайн заменяет их
настоящей речью пользователя, не трогая код приложения и формат
контента.

**Пересмотр решения:** первая версия этого дизайна планировала
временную озвучку через TTS (`say`/Milena) с последующей заменой на
живую запись. Пользователь решил не проходить через TTS-заглушку и
записать голос сама сразу. Вместо генератора речи строим **интерактивный
инструмент записи**, который проводит по списку слов одно за другим —
как обычный CLI-визард, а не одноразовый скрипт.

### Что входит в этот дизайн

- Интерактивный CLI-инструмент записи на базе `ffmpeg`/AVFoundation
  (запись с микрофона) + `afplay` (прослушивание для проверки)
- Логика фильтрации/пропуска уже записанного и выбора сцены для сессии
- Процесс прогона и проверки — с явным разделением на то, что
  проверяется автоматически, и то, что пользователь делает сама вручную

### Осознанно вне рамок

- TTS в любом виде — решение отменено, эта версия дизайна его заменяет
- Любые изменения `scene.json`, `AudioPlayerService` или другого кода
  приложения — не требуются, воспроизведение уже устроено так, что ему
  всё равно, какое содержимое лежит в WAV-файле
- CI/автоматический запуск инструмента — это ручной dev-инструмент, как
  и существующий `generate_placeholder_assets.dart`
- Автоматическая проверка качества самой записи (шумы, обрезанные
  слова и т.п.) — контроль на слух остаётся за пользователем в момент
  записи (шаг «прослушать → оставить/переписать»)

## 2. Архитектура

Новый интерактивный скрипт `tool/record_voiceover.dart`. Список задач
(что сказать и куда сохранить) берёт готовым из уже существующего
`buildVoiceoverTasks()` (`tool/src/voiceover_tasks.dart`) — эта часть
инфраструктуры не зависит от источника звука (TTS или живой голос) и
переиспользуется без изменений.

**Поток выполнения:**

1. Через `ffmpeg -f avfoundation -list_devices true -i ""` получает
   список аудио-устройств, печатает его, просит выбрать номер
   микрофона (спрашивается каждый запуск — устройство не запоминается
   между сессиями)
2. Необязательный позиционный аргумент — фильтр по id сцены
   (`dart run tool/record_voiceover.dart kitchen`) — записать только
   одну сцену за присест; без аргумента — весь список из 54
3. **Автопропуск уже записанного:** плейсхолдеры, сгенерированные
   `generate_placeholder_assets.dart`, всегда весят ровно 6444 байта
   (0.4 сек тишины, 8000 Hz, 16 бит). Инструмент включает в очередь
   только те файлы, чей текущий размер равен 6444 байтам — то есть
   ещё не переписанные настоящей записью. Это даёт возможность
   останавливаться и продолжать в другой день без отдельного файла
   прогресса
4. Для каждой задачи из очереди, по порядку:
   - печатает `Скажи: «Тарелка» (7/54)`
   - ждёт Enter → стартует запись во временный WAV (44100 Hz, моно,
     16 бит) через `ffmpeg -f avfoundation -i ":<device>" ...`
   - ждёт следующий Enter → останавливает запись, посылая процессу
     `SIGINT` (штатный способ для `ffmpeg` корректно закрыть файл)
   - проигрывает записанное через `afplay` для проверки на слух
   - спрашивает: **[K]** оставить / **[R]** переписать / **[S]**
     пропустить — `K` копирует временный файл в целевой путь (тот же,
     что уже использует `scene.json`/`AudioPlayerService`), `R`
     повторяет запись того же слова, `S` переходит к следующему,
     оставляя плейсхолдер как есть
5. `--dry-run` — печатает, что и в каком порядке было бы записано
   (после фильтрации по сцене и по «уже записано»), не трогая
   ffmpeg/микрофон — единственный режим, который можно проверить
   автоматически без живого голоса

## 3. Формат записи и интерфейс

- Формат: WAV, 16 бит PCM, моно, **44100 Hz** (выше, чем у старых
  TTS/тишина-плейсхолдеров — для живого голоса разумно не занижать
  качество, а разница в весе файла для однословных клипов ничтожна)
- Управление — только Enter и однобуквенные ответы (`K`/`R`/`S`),
  без сочетаний клавиш и без GUI
- Устройство ввода звука выбирается интерактивно при каждом запуске

## 4. Явное разделение автоматической и ручной части

Сам процесс записи — интерактивный и требует реального голоса в
микрофон, поэтому его не может выполнить ни агент, ни субагент.
Автоматизации подлежит только:

- код инструмента (компилируется, проходит `flutter analyze`)
- `--dry-run` — логика фильтрации по сцене и по «уже
  записано»/плейсхолдер, проверяется unit-тестами как чистая функция
  без реального ffmpeg-процесса

Собственно 54 сессии записи (нажать Enter, сказать слово, прослушать,
подтвердить) выполняет пользователь сама, вручную, после того как
инструмент готов и проверен.

## 5. Прогон и проверка

- Реализация: `tool/record_voiceover.dart` + чистая, тестируемая
  функция фильтрации (что попадает в очередь по фильтру сцены и по
  байт-размеру плейсхолдера), закрытая unit-тестами
- Автоматическая проверка: `flutter analyze` + `flutter test` +
  `dart run tool/record_voiceover.dart --dry-run` (и с фильтром по
  сцене), сверка напечатанного списка с ожидаемым
- Ручная проверка: реальная сессия записи проводится пользователем
  вне автоматизированного цикла задач
- Бинарные `.wav`, записанные вручную, коммитятся в репозиторий по
  мере записи — так же, как остальные ассеты сцен сейчас
- На уже установленном приложении свежезаписанное аудио объектов не
  зазвучит само по себе: `DemoContentSeeder.seedIfEmpty` копирует
  бандл в кэш только при пустом кэше, а воспроизведение читает именно
  из кэша. Чтобы проверить новую запись, нужно очистить данные
  приложения или переустановить его. (Системные фразы обновляются
  сразу — они играют прямо из бандла.)
